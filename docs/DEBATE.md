# Debate — Personal Site

## บันทึกการสนทนา (ย่อ)

### รอบ 1 — เปิดประเด็น

- **Brand:** ตัวตนชัด — valentine · Carry · Phantom Assassin · tagline "ฟาร์มในเงามืด แล้วปิดเกมในจังหวะเดียว" · headline ใหม่ไม่เคลมเกินแล้ว แต่ Audience 4 กลุ่มกว้างไป และ Bio ยังเล่าแบบเป็นกันเอง ปิดด้วย "ทักมาได้เลย" ขัดกับกติกาเสียงใน Tone
- **UX:** Home/About มีเนื้อพอ · Interests ยังซ้ำกับ Home (Dota 2 / วิเคราะห์ / ไต่แรงค์) · Contact ไม่มีปลายทางจริง (`demo@example.com` · github/linkedin ว่าง) · Guestbook อยู่ใน nav ทั้งที่ API ยังตอบ 501
- **Devil:** ความเสี่ยงใหญ่คือ Bio "ต่อจิ๊กซอว์" ได้ (ประถม + ร้านเกม + แชมป์โรงเรียน + ทำงานควบคู่) · ถ้า "valentine" ซ้ำชื่อในเกม คนค้นเจอ Steam ID ได้เอง · Rank Journey แบบกรอกเองตรวจสอบไม่ได้ · Guestbook เปิดทาง spam/doxxing

### รอบ 2 — ตอบโต้

- **Brand → Devil:** "แชมป์โรงเรียน" เป็น proof ชิ้นเดียวที่มี ถ้าตัดทิ้ง brand เหลือแต่คำพูด · **Devil:** proof ที่ยืนยันไม่ได้และโยงตัวตนได้ ไม่คุ้ม — Hero Pool 5 ตัว + สไตล์การเล่นเป็น proof ที่ปลอดภัยกว่า · **ตกลง:** v1 ไม่ใช้เรื่องแชมป์ ใช้ Hero Pool เป็นหลักฐานแทน
- **UX → Brand:** nav แบบธีม ("ตัวตน / สนามที่เล่น / เรียกตัว") สวยแต่ผู้เยี่ยมครั้งแรกเดาไม่ออก · **Brand:** ยอมให้ nav เป็นคำไทยตรง ๆ ขอเก็บโทนไว้ที่ CTA และหัว section · **ตกลง:** nav ชัดก่อน โทนอยู่ที่ CTA
- **Devil → UX:** ฟอร์ม Contact เก็บอีเมลผู้ส่งลง SQLite — เว็บที่ขายเรื่อง privacy ต้องบอกผู้ส่งด้วย และช่อง "เรื่อง" ทำให้ต้องแก้ API ฝั่ง OpenCode · **UX:** ยอมตัดช่องเรื่อง แต่ต้องมีบรรทัดบอกเวลาตอบกลับ + ข้อความ error ภาษาคน
- **UX → Devil:** ถ้าตัด Rank Journey ทั้งหมด Home จะไม่มี "ตอนนี้อยู่ตรงไหน" · **Devil:** ใช้ข้อความ "เป้าหมาย: Immortal" บรรทัดเดียวพอ ไม่ต้องมีตัวเลข · **Brand:** headline ใหม่มี "กำลังไต่สู่ Immortal" อยู่แล้ว — ไม่ต้องมี section แยก
- **Brand → UX:** Hero Pool ยังไม่มีเหตุผลรายตัว หน้า Interests จะเป็นแค่รายชื่อ · **UX:** เหตุผลต้องมาจากเจ้าของ ไม่ให้ agent แต่ง — เป็นเงื่อนไขก่อน Lab 04

## Brand Strategist

**Positioning:** ชัดและพร้อมใช้ — Name "valentine" · Headline "Carry สาย Phantom Assassin · กำลังไต่สู่ Immortal" · Tagline "ฟาร์มในเงามืด แล้วปิดเกมในจังหวะเดียว" · ไม่ต้องแก้ headline เพิ่ม

**Audience:** หลัก = ทีม e-sports/แมวมอง + เพื่อนร่วมปาร์ตี้ · รอง = นายจ้าง (ผ่าน About มุม B "ปรัชญานักลอบสังหาร": อดทน วางแผน รอจังหวะ) · คนดูสตรีมพักไว้จนกว่าจะมีช่องที่ใช้นามแฝง

**ข้อเสนอ:**
1. Bio เวอร์ชันเว็บเขียนใหม่ให้ตรงกติกาเสียงใน Tone — สั้น 3 ประโยค (สไตล์ → ปรัชญา → เป้าหมาย) · ตัด "ทักมาได้เลย"
2. ใช้ tagline ซ้ำเป็น signature ที่ Hero · ท้าย About · หัวฟอร์ม Contact
3. ให้ Hero Pool (PA + PL · LS · Slark · Spectre · Razor) เป็น proof แทนคำเคลม — ทุกตัวเป็นสาย Carry ฟาร์มยาว ตรงกับ tagline
4. ยอมตาม UX: nav ใช้คำไทยตรง ๆ · โทนนักลอบสังหารอยู่ที่ CTA ("ส่งสัญญาณมา") และหัว section

## UX Critic

**ความพร้อม 4 หน้า:**

| หน้า | สถานะ | ต้องมีอะไรเพิ่ม |
|---|---|---|
| Home | พร้อม | Hero (ชื่อ/headline/tagline) + CTA ไป Contact · ตัด section Rank Journey |
| About | เกือบ | Bio เวอร์ชันเว็บมุม B (เจ้าของเขียน) |
| Interests | ยังไม่พร้อม | เหตุผล 1 บรรทัดต่อฮีโร่ใน Hero Pool — ไม่งั้นซ้ำกับ Home |
| Contact | ยังไม่พร้อม | ปลายทางจริงที่ใช้นามแฝง หรือยืนยัน "ฟอร์มอย่างเดียว" · ซ่อนข้อความนักพัฒนา |

**จุดที่ผู้เยี่ยมจะสับสน:** Guestbook ใน nav/การ์ด Home แต่ใช้ไม่ได้ · ภาษาไทยปนอังกฤษใน UI (Home, Send, "Sent. Thank you!") · CTA ไม่บอกว่ากดแล้วได้อะไร · ท้าย About/Interests ไม่มีทางไปต่อ · error แสดงโค้ดดิบ · ข้อความ "อัปเดต…เร็ว ๆ นี้" ทำให้หน้าดูยังไม่เสร็จ

**IA:** Home = ใคร + กำลังไปไหน · About = ทำไมเล่นแบบนี้ · Interests = Hero Pool + สิ่งที่สนใจ · Contact = เรียกตัว · nav 4 ลิงก์ Contact ขวาสุดและเด่นสุด · ทุกหน้าจบด้วย CTA เดียวกัน

**Microcopy:** nav "หน้าแรก · เกี่ยวกับ · ความสนใจ · ติดต่อ" · CTA "ส่งสัญญาณมา" · ปุ่ม "ส่ง" / "กำลังส่ง…" · สำเร็จ "ได้รับแล้ว จะตอบกลับทางอีเมลที่ให้ไว้" · ผิดพลาด "ส่งไม่สำเร็จ ลองอีกครั้ง" · ใต้หัวฟอร์ม "ตอบกลับภายใน 2–3 วัน"

## Devil's Advocate

**ความเสี่ยง:**

| # | ความเสี่ยง | ระดับ |
|---|---|---|
| R1 | Bio ต่อจิ๊กซอว์ตัวตนได้ (ประถม · ร้านเกม · แชมป์โรงเรียน · ทำงานควบคู่) | สูง |
| R2 | "valentine" อาจซ้ำชื่อในเกม/Discord → ค้นเจอ Steam ID โดยไม่ต้องมีลิงก์ | สูง |
| R3 | แรงค์กรอกเองตรวจสอบไม่ได้ · ถ้าไม่อัปเดตหน้าเว็บจะผิดเอง | สูง |
| R4 | Guestbook = spam / คุกคาม / doxxing โดยคนรู้จัก — ต้องมี moderation ไม่ใช่แค่กรองคำ | สูง |
| R5 | ฟอร์ม Contact เก็บอีเมลผู้ส่งลง SQLite โดยไม่บอกว่าเก็บนานแค่ไหน · ไม่มีกันสแปม | กลาง |
| R6 | ไม่มีช่องทางติดต่อจริง — CTA ทุกหน้าไปจบที่ทางตัน | กลาง |
| R7 | Must ที่ดูเล็ก (ฟอร์มแยกเรื่อง · Rank Journey) แตกเป็นงานข้าม owner (API/DB ฝั่ง OpenCode) | กลาง |
| R8 | URL · ชื่อ repo · git author อาจมีชื่อจริง — หน้าเว็บปลอดภัยแต่ metadata หลุด | กลาง |

**คำถามที่ต้องตอบก่อน ship:**
1. "valentine" ใช้ในเกม/Discord/โซเชียลด้วยไหม — ค้น "valentine Dota" แล้วเจออะไร
2. URL เว็บ · ชื่อ learner repo · git author มีชื่อจริงไหม
3. ข้อความ Contact ไปถึงเจ้าของทางไหน · เก็บนานเท่าไร · ใครลบ
4. มีอีเมลที่ใช้นามแฝงหรือยัง — ถ้าไม่มี ship Contact แบบไหน
5. Guestbook มีใครดูแลไหม — ถ้าไม่มี ทำไมต้องเปิด

**ตัดจาก Must:** Rank Journey (→ ข้อความบรรทัดเดียวใน headline) · ช่อง "เรื่อง" ในฟอร์ม · การ์ด Playstyle (รวมเข้า Hero) · Guestbook ไม่อยู่ใน v1 ทั้ง UI และ route
